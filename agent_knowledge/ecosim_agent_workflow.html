ecosim-agent Workflow

Agent knowledge note · 14 October 2026 · Describes the ecosim-agent skills on branch feature/multisite-project (main plus full-run continuation, the gSSURGO FC/WP fix, and multi-site projects). Links are relative to this repository.

ecosim-agent turns a request such as “create an ecosim run folder for site US-UMB” into a checked, runnable EcoSIM case. It prepares site inputs from AmeriFlux, ERA5, gSSURGO, NADP/tDEP, and BADM data; builds a self-contained run folder; runs a 2-year smoke run; corrects implausible plant traits from literature; and records every stage in a progress tracker. The EcoSIM model itself is Fortran in the parent repository; these skills are the Python preprocessing and checking layer.

The four stages

1 · Data preparationSite metadata, climate forcing, precipitation chemistry, soil grid, vegetation and plant management.
2 · Namelist creationRun folder result/<SITE>/{input,run_dir}, namelist, chronology.
3 · Model simulationBuild, 2-year smoke run, plant-trait check and correction, full run.
4 · Output evaluationTarget extraction and comparison with tower and site observations.
Progress tracker (ecosim-site-run-tracker): result/<SITE>/progress.json and PROGRESS.md, refreshed by every site-input script

Stages 1–3 up to the smoke run are what “create a run folder” means. The full simulation and output evaluation run only when the user asks.

Result layout

ecosim-agent/result/<SITE_ID>/
  input/       site NetCDF (grid, climate_<first>-<last>, pft_mgmt), Excel/JSON sidecars,
               reports, site vegetation, trait evidence and correction logs, and copies of
               the PFT parameter (site-corrected copy), GHG, and microbial parameter files
  run_dir/     <SITE_ID>.namelist (all paths ../input/...) and, after running, model output
  smoke_run/   2-year smoke run, its plant_trait.desc, trait-check report, smoke_summary.json
  evaluation/  output-evaluation products (optional)
  progress.json, PROGRESS.md

Stage 1 · Data preparation

  1. Start. Show the startup notice, inventory local data (ecosim-data-readiness), and initialize the tracker with the request text. Source data are staged under data/ (a link to the shared data folder): AmeriFlux FULLSET/ERA5 archives, gSSURGO_CONUS.gdb, FAO HWSD2, NADP grids, tDEP rasters, and the network BADM file AMF_AA-Net_BIF_*.xlsx.
  2. Site metadata (ameriflux-site-info): latitude, longitude, elevation, mean annual temperature, Köppen class, IGBP type. Every extraction is cross-checked: parsed signs against the raw page, coordinates against the site-ID country, Description region words, Köppen versus temperature, and Köppen from coordinates on a gridded map (--koppen-raster). Sign or country failures stop the extraction.
  3. Climate forcing (ameriflux-era5-to-ecosim via Tools/create_ecosim_climate_forcing.py): ERA5 half-hourly to hourly NetCDF with
    • ERA5–tower time registration: cross-correlating shortwave with tower SW_IN_F and shifting late ERA5 files onto the tower clock (several AmeriFlux releases are one hour late);
    • ZNOONG as local solar noon on the forcing clock (EcoSIM caps hourly radiation with the sun angle from it);
    • DWPTH as actual vapor pressure, es(T) − VPD, which is what EcoSIM reads;
    • NADP precipitation chemistry, gap-filled across years;
    • a file named by its years, <SITE>_ecosim_climate_<first>-<last>.nc, and a comparison with measured tower meteorology.
  4. Soil grid (ameriflux-surgo-grid-extract via Tools/create_ecosim_grid_forcing.py): dominant gSSURGO component interpolated to EcoSIM layers. Field capacity and wilting point are gSSURGO whole-soil volumetric contents divided by (1 − rock) to match EcoSIM’s rock-free matrix. Missing values are gap-filled (organic-horizon defaults, nearest layer, or −1 so EcoSIM estimates FC, WP, Ksat, CEC); layers with FC ≤ WP are left to the model; the file is rejected if any layer EcoSIM reads is invalid.
  5. Vegetation: dominant species and canopy shares from BADM (site_vegetation.py extract), or published site descriptions when BADM lacks them; the PFT code (ecosim-vegetation-code) must exist for the grid’s Köppen suffix, because EcoSIM replaces the suffix.
  6. Plant management (ecosim-natural-plant-mgmt): planting density from literature stem counts, depth, and 12 monthly thinning events for trees without biomass export. Soil management (ecosim-soil-mgmt) only for managed sites; otherwise the tracker step is marked skipped with the reason.

The combined path is unified-ameriflux-extractor, which runs chemistry, soil, climate, and grid in one call and reports any step that fails.

Stage 2 · Namelist creation

python .agents/skills/ameriflux-namelist-generator/scripts/create_site_run_folder.py --site-id <SITE>

Moves site artifacts into input/, copies the shared parameter files (or keeps the site-corrected PFT copy), writes run_dir/<SITE>.namelist, and verifies that every path resolves to ../input/. Default chronology repeats the first four forcing years 18 times for spinup, starts that many years before the forcing record, and sets stop_n to EcoSIM’s own run length, Σ (end − start + 1) × cycles over forc_periods (US-UMB: start 1909, stop_n 113).

Stage 3 · Model simulation

Build

Build in the VSCode integrated-terminal environment (shell, PATH, CC/CXX/FC from VSCode settings), reusing a build directory whose compilers match, with bash build_EcoSIM.sh. Report the toolchain.

Smoke run and plant-trait correction

python .agents/skills/ameriflux-namelist-generator/scripts/create_site_smoke_run.py --site-id <SITE>
  1. Run 2 simulated years in smoke_run/; pass only with exit 0, every hourly step (leap days counted), and history without NaN/Inf.
  2. Check the plant_trait.desc the run writes with ecosim-plant-trait-sanity-check in strict physiology mode. The .desc file is read-only.
  3. Build trait evidence following the site’s vegetation: site measurements (BADM LMA → SLA1, foliage N:C → CNLF) > dominant species > genus > functional type, weighted by canopy share, linted for level, taxa, and citation (site_vegetation.py site-evidence | weight | lint).
  4. Correct severe findings in a site copy, input/<SITE>_ecosim_pftpar.nc, with ParEditor (ecosim-pftpar-editor) and repeat the smoke run until fixed, two consecutive iterations change nothing, or four rounds pass.
FindingCorrection rule
Numeric value outside a literature rangeMidpoint of the sourced range
SLA10.25 × the typical (midpoint) value; resolved once equal to that target
Rubisco kinetics (VCMX/VOMX/XKCO2/XKO2)Keep VCMX, XKCO2, XKO2; set VOMX to the literature specificity midpoint
Categorical identity (IEBTYP, ISNTYP)EcoSIM enum code from ElmIDMod.F90
CHL for C3 trees, no literature valueUser default 0.12, recorded as user-default, with the resulting Jmax:Vcmax
Anything without literature evidenceLeft unresolved and reported; never an invented value

CHL and ETMX act as a pair. In the C3 path, Jmax = ETMX × CHL × leaf protein C / 3.5 (StomatesMod.F90), so only their product matters to photosynthesis. Changing CHL alone rescales Jmax by the same factor.

Full run

nohup python .agents/skills/ameriflux-namelist-generator/scripts/run_site_full.py --site-id <SITE> > /dev/null 2>&1 &

Only on request. The run passes with exit 0, every planned hourly step, and history without NaN/Inf. If it fails partway, the script continues it once by setting continue_run=.true. in the run namelist: EcoSIM reads the restart in rpointer.esim, skips forcing years before the restart date, and ends at the end of the plan, so stop_n is unchanged. If the continued run also fails, the error is reported with both log tails in run_dir/full_run_summary.json, which the tracker reads. Any change to inputs or traits after a full run makes that run stale.

Stage 4 · Output evaluation

Extract targets from h0 history with ecosim-h0-target-extractor into evaluation/, compare with tower fluxes and site observations, and condition judgments on stand age: a cohort grown from seed in the simulation is not the mature stand at the tower.

Multi-site projects

For a set of sites, each site goes through stages 1–3 in its own result/<SITE>/; ecosim-multisite-project then sorts the finished cases into one project:

python .agents/skills/ecosim-multisite-project/scripts/assemble_project.py --project <PROJECT> --sites US-UMB US-xGR

result/projects/<PROJECT>/
  input/<SITE>/      the site's inputs
  run_dir/<SITE>/    <SITE>.namelist with paths ../../input/<SITE>/...
  project.json, PROJECT.md   per-site chronology, stage, smoke, and trait status

Sites without a passed smoke run are reported and left out; reassembly refreshes sites without touching others or existing model output. Full runs use run_site_full.py --run-dir result/projects/<PROJECT>/run_dir/<SITE>.

Guardrails

  • Plant-trait .desc files are never edited; trait changes go to the PFT parameter NetCDF through ParEditor, in a site copy, with a backup and change log.
  • Every corrected parameter value cites literature (source, URL, evidence level, conversion); the only exception is the C3 tree CHL default.
  • Enum codes come from f90src/Modelconfig/ElmIDMod.F90, not NetCDF flag text (the PFT file’s IEBTYP flags are off by one).
  • Scripts fail loudly: missing outputs, invalid soil layers, unresolved paths, or smoke-run failures stop the step and are recorded in the tracker.
  • Commits are local unless the user says “commit to remote”; the data link and result/ stay untracked.

Known limitations

  • FAO HWSD2 fallback cannot read HWSD2.mdb without an MDB driver; export HWSD2_LAYERS.csv to enable it.
  • Leaf N and P, light-harvesting fractions, and root vessel sizes are often found only at genus level or from stems; reports label the evidence level.
  • SLA1 under the 0.25 rule stays below literature ranges by design and is always reported as a warning.
  • The network BADM file is a dated snapshot (2025-08-28); a site’s own newer BIF takes precedence.
  • Output evaluation against tower fluxes is not yet automated.
